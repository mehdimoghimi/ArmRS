# نقشه راه اجرای پایان‌نامه
## سیستم توصیه‌گر مکالمه‌ای مبتنی بر LLM + Association Rule Mining

> دیتاست: [Amazon Reviews 2023 (McAuley Lab)](https://amazon-reviews-2023.github.io/)

---

## 🎯 خلاصه اجرایی: از کجا شروع کنم؟

همین امروز این ۳ کار رو انجام بدید:
1. یک دسته محصول رو قطعی کنید و نسخه **5-core** اون رو دانلود کنید (نه فایل خام کامل)
2. محیط پایتون + یک API key از OpenAI (یا مشابه) رو راه‌اندازی کنید
3. فقط دیتا رو باز کنید و ۲۰-۳۰ نمونه رو با چشم ببینید — قبل از نوشتن حتی یک خط کد پردازش

جزئیات کامل هرکدوم در فاز ۰ و ۱ زیر اومده.

## بخش اول: نقشه راه فنی (Phase 0 تا Phase 10)

### Phase 0 — راه‌اندازی محیط (۱-۲ روز)

| کار | جزئیات |
|---|---|
| محیط پایتون | `python -m venv venv` + نصب: `pandas`, `mlxtend` (برای ARM), `openai` (یا SDK مدل انتخابی‌تون), `scikit-learn`, `matplotlib` |
| دسترسی API | یک حساب OpenAI بسازید، مدل و نسخه دقیقش رو همین الان یادداشت کنید (برای بخش Reproducibility پروپوزال‌تون) |

| ساختار پوشه پیشنهادی | `data/raw`, `data/processed`, `src/arm`, `src/llm`, `src/eval`, `notebooks/`, `results/` |

### Phase 1 — انتخاب و دانلود دیتاست (۲-۳ روز)

**تصمیم مهم اول: کدوم Category؟**

بر اساس بررسی مستقیم صفحه دیتاست، نسخه کامل هر Category خیلی بزرگه (میلیون‌ها رکورد) و برای یک پایان‌نامه قابل مدیریت نیست. McAuley Lab خودش نسخه **5-core** (فقط کاربران/محصولاتی که حداقل ۵ تعامل دارن) رو آماده کرده که خیلی کوچیک‌تره:

| Category | کاربر (5-core) | محصول (5-core) | تعداد رتبه‌بندی (5-core) |
|---|---|---|---|
| **Cell_Phones_and_Accessories** ✅ پیشنهادی | 381.0K | 111.5K | 2.8M |
| **Electronics** | 1.6M | 368.2K | 15.5M |
| Video_Games | 94.8K | 25.6K | 814.6K |
| Software | 146.4K | 17.6K | 1.3M |

**پیشنهاد من: `Cell_Phones_and_Accessories`.** چون همون دامنه‌ایه که در کل پروپوزال (مثال «لپ‌تاپ»، «گوشی با دوربین خوب») استفاده کردید، و نسبت به Electronics کوچیک‌تر و مدیریت‌پذیرتره. حتی این هم برای شروع بزرگه — در فاز ۲ بیشتر کوچیکش می‌کنیم.

**لینک‌های دانلود مستقیم (تأیید‌شده):**
- فایل rating-only پنج‌هسته‌ای: `https://mcauleylab.ucsd.edu/public_datasets/data/amazon_2023/benchmark/5core/rating_only/Cell_Phones_and_Accessories.csv.gz`
- فایل کامل ریویوها (برای متن/امتیاز): `https://mcauleylab.ucsd.edu/public_datasets/data/amazon_2023/raw/review_categories/Cell_Phones_and_Accessories.jsonl.gz`
- فایل متادیتای محصول: `https://mcauleylab.ucsd.edu/public_datasets/data/amazon_2023/raw/meta_categories/meta_Cell_Phones_and_Accessories.jsonl.gz`

**⚠️ نکته فنی مهم که باید بدونید:** فیلد `also_view`/`also_viewed` که قبلاً در نسخه‌های قدیمی‌تر دیتاست Amazon وجود داشت، **در نسخه 2023 دیگه نیست**. فقط فیلد `bought_together` هست که در اکثر محصولات مقدارش `null` هست (خیلی کم‌داده). یعنی **نباید** روی این فیلد برای ساخت قوانین انجمنی حساب کنید — باید خودتون از روی رفتار کاربران (چه کسی چه چیزهایی رو خریده) تراکنش بسازید. این دقیقاً همون چیزیه که در بخش Dataset پروپوزال‌تون هم نوشتید («رفتار خرید به‌صورت ضمنی استنباط می‌شود») — پس این محدودیت از قبل پیش‌بینی شده، خیالتون راحت باشه.

### Phase 2 — آماده‌سازی داده و ساخت «تراکنش» (۱ هفته)

قدم‌به‌قدم:

1. فایل `Cell_Phones_and_Accessories.csv.gz` (نسخه 5-core) رو با `pandas.read_csv` باز کنید — ستون‌هاش: `user_id, parent_asin, rating, timestamp`
2. **تعریف تراکنش:** هر کاربر = یک «سبد خرید فرضی» = مجموعه همه `parent_asin` هایی که اون کاربر ریویو کرده (ترجیحاً فقط `rating >= 4` تا نویز کمتر بشه)
3. برای مدیریت حجم: یک نمونه تصادفی از ۵,۰۰۰ تا ۱۰,۰۰۰ کاربر با بیشترین تعداد تعامل انتخاب کنید (نه کل ۳۸۱ هزار کاربر) — این برای نسخه اول پایان‌نامه کاملاً کافیه و توسط بسیاری از مقالات RecSys هم انجام می‌شه
4. فایل متادیتا (`meta_Cell_Phones_and_Accessories.jsonl.gz`) رو جداگانه بخونید و بر اساس `parent_asin` به تراکنش‌ها join کنید — از این فایل فیلدهای `title`, `price`, `store` (برند), `categories`, `details` (شامل Brand/Color/Size) رو نگه دارید، چون این‌ها دقیقاً همون چیزهاییه که در بخش «زنجیره فنی» پروپوزال‌تون (`category`, `usage`, `budget_max`) بهش نیاز دارید
5. خروجی این فاز: دو فایل تمیز — `transactions.csv` (user_id → لیست parent_asin) و `products.csv` (parent_asin → title, price, brand, category)

**چک‌لیست پایان فاز ۲:** آیا می‌تونید برای یک کاربر دلخواه، لیست محصولاتش رو با قیمت و نام واقعی چاپ کنید؟ اگه بله، آماده فاز بعدی هستید.

### Phase 3 — موتور ARM (۱ هفته)

1. با کتابخانه `mlxtend` (تابع `apriori` یا `fpgrowth`) روی `transactions.csv` قوانین انجمنی استخراج کنید
2. خروجی هر قانون باید شامل: `antecedent`, `consequent`, `support`, `confidence`, `lift` باشه
3. قوانین با `confidence` یا `lift` خیلی پایین رو فیلتر کنید (مثلاً `lift > 1` و `confidence > 0.1` نقطه شروع خوبیه، بعداً tune کنید)
4. این قوانین رو در یک فایل/دیتابیس ساده (حتی یک فایل SQLite یا CSV) به‌عنوان «مخزن دانش» ذخیره کنید
5. یک تابع ساده `retrieve_rules(category, budget_max)` بنویسید که قوانین مرتبط رو برمی‌گردونه — این دقیقاً همون چیزیه که در «زنجیره فنی» پروپوزال‌تون قدم ۲ و ۳ هست

**🎯 نقطه عطف مهم:** وقتی این فاز تموم شد، شما **Baseline شماره ۱ (ARM به‌تنهایی)** رو کامل دارید — یکی از ۵ Baseline پروپوزال‌تون از همین‌جا آماده می‌شه. این رو جشن بگیرید، اولین سنگ‌بنای قابل‌ارزیابی سیستم‌تونه.

### Phase 4 — لایه LLM: استخراج ترجیحات (۱ هفته)

1. یک تابع بنویسید که با API مدل زبانی (GPT)، از جمله کاربر (فارسی یا انگلیسی) یک JSON ساختاریافته استخراج کنه: `{category, usage, budget_max, brand_pref, ...}`
2. Prompt رو دقیقاً مطابق مثالی که در پروپوزال نوشتید طراحی کنید (`"یک لپ‌تاپ برای برنامه‌نویسی تا ۵۰ میلیون تومان"` → JSON)
3. `temperature` رو پایین (مثلاً 0.2) بذارید و **همه** promptها و پاسخ‌ها رو در یک فایل log کنید (طبق تعهدی که در پروپوزال دادید)
4. تست کنید: با ۱۰-۱۵ جمله واقعی متفاوت (شامل جملات مبهم و ناقص) ببینید JSON خروجی چقدر درسته

### Phase 5 — اتصال LLM به ARM: زنجیره کامل (۱ هفته)

1. خروجی JSON مرحله قبل رو به کوئری قابل اجرا روی مخزن قوانین (فاز ۳) تبدیل کنید
2. قوانین بازیابی‌شده رو بر اساس confidence/lift رتبه‌بندی و aggregate کنید (طبق تعریف Reasoning در پروپوزال)
3. `consequent` قوانین رو به محصولات واقعی (از `products.csv`) نگاشت و بر اساس بودجه فیلتر کنید
4. لیست نهایی + متادیتای قانون رو به LLM بدید تا توضیح تولید کنه — با محدودیت صریح در prompt: **"فقط از اعداد و اطلاعات داده‌شده استفاده کن، هیچ عدد جدیدی نساز"**

**🎯 نقطه عطف مهم:** الان **نسخه اول کامل سیستم پیشنهادی (LLM+ARM بدون Feedback)** رو دارید — Baseline شماره ۴ پروپوزال‌تون. از اینجا به بعد، هرچی اضافه کنید بهبوده، نه پیش‌نیاز.

### Phase 6 — حلقه بازخورد (۴-۵ روز)

1. یک state ساده نگه دارید که ترجیحات فعلی کاربر رو در طول مکالمه ذخیره می‌کنه
2. بعد از هر پاسخ کاربر («نه ارزون‌تر می‌خوام»، «برند سامسونگ نه»)، LLM این پیام رو تحلیل کنه و state رو به‌روزرسانی کنه (نه fine-tune، فقط به‌روزرسانی متغیرهای preference)
3. با state جدید، دوباره فاز ۵ رو صدا بزنید

با این کار، سیستم کامل (Baseline ۵ — نسخه نهایی) هم آماده می‌شه.

### Phase 7 — Baselineهای مقایسه‌ای (۱ هفته)

طبق جدول پروپوزال، این دو مورد باقی مونده رو هم بسازید:
- **Baseline 2 (LLM به‌تنهایی):** فقط prompt بدید که بدون دسترسی به قوانین ARM، مستقیم پیشنهاد بده — برای نشون دادن اینکه چرا ARM لازمه
- **Baseline 3 (Chat-Rec):** طبق توضیح مقاله Gao et al. (2023)، یک نسخه ساده بازتولید کنید (نیازی به کد اصلی نیست — فقط منطق کلی‌شون: تاریخچه کاربر + پروفایل مستقیم در prompt، بدون قوانین ساختاریافته)

### Phase 8 — چارچوب ارزیابی (۱-۲ هفته)

1. **معیارهای کیفیت توصیه:** یک تابع بنویسید که برای یک کاربر، محصول واقعی خریداری‌شده در آینده (که در تراکنش نگه داشتید ولی به مدل ندادید — همون Leave-Last-Out) رو با پیشنهاد سیستم مقایسه کنه و NDCG@K, Recall@K, Precision@K, MRR حساب کنه
   - نکته فنی: خود دیتاست نسخه آماده leave-last-out splitting رو هم داره — می‌تونید مستقیم استفاده کنید تا وقت صرف نویسی split نشه: `.../benchmark/5core/last_out_w_his/Cell_Phones_and_Accessories.test.csv.gz`
2. **معیارهای مکالمه:** تعداد turn، Success Rate، Response Time — این‌ها رو موقع اجرای سناریوهای تست به‌صورت خودکار لاگ کنید
3. **معیارهای کاربر (Satisfaction/Trust):** یک پرسشنامه کوتاه لیکرت (۵ تا ۷ گویه) طراحی کنید و با حداقل ۱۵-۲۰ نفر (همکلاسی، دوستان، هر کاربر واقعی در دسترس) روی چند سناریوی از پیش تعریف‌شده تست کنید — این بخش زمان‌بره، زودتر شروعش کنید

### Phase 9 — Ablation Study (۳-۴ روز)

با همون چارچوب فاز ۸، سه پیکربندی `ARM` / `ARM+LLM` / `ARM+LLM+Feedback` رو روی یک مجموعه تست ثابت اجرا و نتایج رو در یک جدول/نمودار مقایسه کنید.

### Phase 10 — نگارش (موازی با فازهای ۷ تا ۹ شروع کنید، نه بعدش!)

از همون فاز ۳ به بعد، هر بخش که کامل شد، همون هفته در فصل روش‌شناسی پایان‌نامه بنویسیدش — نه اینکه همه رو بذارید آخر.

## بخش دوم: نقشه‌ی مقاله‌ها

با توجه به حجم کار یک پایان‌نامه کارشناسی ارشد (~۹ ماه)، واقع‌بینانه ۱ تا ۲ مقاله قابل استخراجه. دو مسیر پیشنهادی:

| مقاله | محتوا | زمان پیشنهادی | Venue پیشنهادی (واقع‌بینانه) |
|---|---|---|---|
| **مقاله اصلی (سیستم)** | معماری کامل LLM+ARM + نتایج آفلاین (NDCG/Recall) + Ablation | بعد از فاز ۹ (حدود ماه ۷-۸) | یک ورک‌شاپ معتبر مرتبط با RecSys/SIGIR/CIKM (مثلاً ورک‌شاپ‌های LLM for Recommendation) — نقطه شروع کم‌ریسک، یا یک کنفرانس داخلی/مجله علمی-پژوهشی معتبر داخلی |
| **مقاله دوم (اختیاری، اگر وقت بود)** | نتایج مطالعه کاربری روی Trust/Explanation Quality — زاویه HCI/Explainability | بعد از فاز ۸ (بخش کاربری) | ورک‌شاپ‌های Explainable AI یا IUI |

**توصیه واقع‌بین:** بذارید اول پروتوتایپ کامل کار کنه (فاز ۰ تا ۹)، بعد تصمیم بگیرید کدوم بخش نتیجه‌ی قوی‌تری داده و همون رو مقاله کنید. تلاش برای نوشتن مقاله زودتر از داشتن نتایج واقعی، معمولاً وقت تلف می‌کنه.
